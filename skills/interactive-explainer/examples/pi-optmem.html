The problem it solves

Stock OptMem is a light switch for the whole house.

OptMem's instructions normally live in AGENTS.md. Every session then reads memory, writes memory and pays for the wake view, including quick fixes, client work and subagents.

Before: a block in AGENTS.md

vault
work repo
quick fix
subagent

Everything is on. Subagents can write notes. A throwaway session fills memory with noise.

After: pi-optmem

vault · on
work · read
quick fix · off
subagent · off

Each session gets the prompt, wake view and tools for its mode. Subagents are capped, and never write.

What reaches the model

The wake view rides along with each request, and is never saved.

The extension holds the wake view in memory and adds it just before the model call. Compaction and branch summaries never see it, so turning memory off really removes it.

How memory is shaped

A binary tree of one-line memories.

The wake view shows summaries of whole ranges. The agent zooms into a range when it needs detail, and naps a range into one line when memo asks for compression.

Click a #a-b line to call memo_zoom. Leaves are raw memories, at most 280 bytes each.

Try the bash guard

It blocks first and asks no questions.

The memo tools check the mode themselves. Bash is the side door, so the guard fails closed: anything unusual that mentions memo is blocked.
